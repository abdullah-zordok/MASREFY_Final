# Private Voice journal diagnostic preparation

This directory contains **local preparation code**, not an installed or approved Redmi diagnostic. No class calls the Masarifi app, a service, API, provider, database loader or key-generation routine. The qualified application7967007 and its APK/image are preserved.

`VoiceStoreSnapshot` captures allowlisted owner/legacy SQLite stores and WAL/SHM/journal sidecars, legacy RKStorage, and existing key preferences into bounded memory. It reads using no-follow leaf access and checks parent directories, file stamps and before/after inventories. Limits are64MiB total and512 files. Verification streams64KiB chunks instead of allocating a second snapshot. Unknown Voice store names, orphan sidecars, preference backups, symlinks, unreadable files, root/inventory changes and exceeded limits fail closed. Only a genuine missing-file exception is treated as absence; denied/unknown access is indeterminate. Failed captures clear already retained byte arrays through finally cleanup, including allocation failures; `close()` clears a completed capture. The public summary contains counts and an aggregate fingerprint; it has no no-replay verdict, filenames, keys, IDs or contents.

Capture requires an independently verified quiescent target package. Java desktop providers may omit inode-like file keys, so creation identity is retained as well and `nativeFileIdentityAvailable=false` explicitly reports that limitation. NTFS can preserve creation time when a filename is replaced, so metadata fallback cannot attest identical-byte inode replacement. A future Android wrapper must additionally verify native UID/inodes and quiescence; the portable component is not a proof against hostile concurrent directory replacement. Native encrypted/committed-WAL reading, strict full-owner journal classification, bootstrap suppression and disposable Android rehearsal are still required by the [implementation plan](../../docs/superpowers/plans/2026-10-11-voice-private-journal-qualification.md).

Run portable preparation tests in a **new** evidence directory:

```powershell
./scripts/android-voice-qualification/run-local-tests.ps1 -OutputDirectory E:/Masarifi-redmi-acceptance-2026-10-10/regression/voice-private-reader-new-run
```

These tests touch only synthetic files created in the host temporary directory and retain those fixtures. Unavailable host symlink/POSIX permission cases are explicitly reported unexecuted; Linux CI requires both to execute. A desktop-only JDK17 SecurityManager boundary denial also tests sanitized failure on Windows; its expected deprecation warning does not apply to production source. A separate96MiB-heap test checks a full64MiB capture and streaming verification. No Android device, real key or application data is read. Passing these tests is not Redmi acceptance or permission to execute instrumentation.

`CommittedWalSnapshot` materializes raw pages through the last validated commit, including repeated pages, database growth and commit truncation. It validates both SQLite checksum byte orders, salts, version, page sizes, every complete frame and growth coverage. Valid uncommitted tails are excluded; corrupt, truncated or stale tails remain indeterminate. It bounds combined input and output separately to64MiB and clears materialized bytes on close or failed ownership transfer. It never opens SQLite or writes a target file. Original rollback journals must still be classified independently before using this component; an absent WAL alone proves nothing about recovery.

The disposable real-WAL fixture test creates its own fresh directory and proves that a processing journal row exists only in committed WAL. A main-file-only read must return0; reconstruction must return1, retain encryption where applicable and create no unexpected reader sidecars. Linux CI compiles the exact checksum-pinned Expo55.0.20 SQLCipher4.7.0 amalgamation with the application's SQLite build options and an independent OpenSSL test library. This verifies raw-page reconstruction on disposable encrypted data; it does not qualify Android keys, the native in-memory VFS, full journal classification or bootstrap suppression. Test classes and fixture-writing tools must never be packaged in the Android diagnostic.

`ExistingDatabaseKey` is an existing-only AES-GCM primitive. Its bounded envelope accepts only the deployed default keychain and unauthenticated AES format. The Android factory uses `AndroidKeyStore.getEntry` for one of the two known current/legacy aliases; it has no generation, deletion, enumeration, authentication prompt or application getter. Decrypted64-byte hex material is decoded in memory and cleared on close/failure. Fixed failure codes omit causes and private data. Host tests use actual AES-GCM with public disposable keys and replace only the existing-key lookup boundary. AndroidKeyStore itself has not been executed. Calling the Android factory or reading a real key requires the separately approved native process scope.

`SecureStoreKeyIndex` maps each owner database's24-character hash prefix to exactly one existing full64-character owner-key entry. It recognizes the deployed `key_v1-masarifi.database.key.<hash>` and older bare `masarifi.database.key.<hash>` formats. Colliding owner prefixes, duplicate current/legacy forms, malformed/unknown key names and duplicate XML names fail closed. Selected encrypted envelopes are parsed lazily; the index never decrypts keys or invokes application getters. It preserves explicit current metadata and older default alias behavior. Actual synthetic AES-GCM tests cover both paths and clear returned key bytes on close.

The XML reader uses strict UTF8 decoding and bounded streaming SAX parsing:4MiB input,512 preference entries,4096 element nodes,4096 characters per relevant encrypted envelope. DTD/comment/CDATA declarations are rejected before parsing; external entity resolution, processing instructions, namespaces, nested relevant values and malformed XML cannot produce an empty result. Unexpected XML-provider runtime/configuration failures yield a sanitized unavailable result. `StrictJson` separately limits input to24576 characters,4096 value nodes,24 levels and64-character numbers. Duplicate normalized object keys, invalid Unicode/JSON, fractional integers and oversized exponents are rejected with fixed private-data-free errors.35 JSON and48 mapping host checks cover these contracts, including current/legacy AES256 fixtures. These parser/crypto preparation checks do not prove Android XML/keystore behavior, complete native journal classification or bootstrap suppression.

`VoiceStoreQualification` now binds that inventory to every owner key, contiguous pinned migration/schema coverage, strict journal rows, legacy ownership/migration markers and unchanged originals. It combines both existing preference files, rejects duplicate/current/older forms and owner-prefix collisions across the whole index, and rejects a key whose owner database is missing. The encrypted legacy owner claim must match exactly one owner's `legacy-export-owner` marker. A surviving plaintext legacy database requires that completed binding and is still inspected independently. Any original rollback journal, including an empty one, remains unclassified and blocks a verdict. Every RKStorage row is read with a fixed query; unrelated typed preferences are ignored, while malformed Voice keys cannot disappear behind a SQL prefix filter. A pending row never short-circuits inspection of other stores.

The result exposes only counts, CLEAR/BLOCKED and the stable aggregate fingerprint. Missing keys, unsupported schemas, bad column types/payloads, incomplete marker ownership, corrupt WAL, unknown providers/readers or changed files yield the fixed `STORE_INDETERMINATE` exception without a private cause. A CLEAR result requires independently established package quiescence and a qualified reader; it is not permission to start or recover the application.

`NativeSnapshotReader` and `voice_memory_jni.c` connect bounded copied arrays to the existing independent SQLCipher RAM VFS. No filename, dynamic SQL, target app handle or loader is accepted. JNI transmits strict length-delimited UTF8 rather than modified UTF8, rejects floating/blob/unknown columns, clears copied text/key/database buffers and sanitizes callback/provider failures. The only additional native query is fixed migration-marker enumeration. Native handles stay private to a synchronized AutoCloseable reader.

The preparation workflow now includes42 real-schema synthetic integration cases through the Linux production JNI library, followed by a dependent disposable Android15 fixture job. The latter packages those exact encrypted/WAL fixtures, checksum-pinned SQLCipher/OpenSSL and separate same-signature synthetic packages. Its synthetic-only seeder imports public AES keys into the fixture UID; the reader then uses the actual existing-only AndroidKeyStore factory through current and older aliases. It repeats complete unchanged-store assertions three times and preserves the six-write/six-request bootstrap positive control. The fixture-only writer/instrumentation is never a candidate private-data probe and cannot target `com.masarifi.mobile`.

All local commands remain host compilation/tests. No local emulator, physical device, ADB, real key or app data is needed or authorized. Offline Android Java/native build success is not Android runtime qualification. The encrypted Linux/JNI and Android15 workflow receipts, fresh installed-package verification, a final real-target probe identity and separately approved physical execution remain external gates.
