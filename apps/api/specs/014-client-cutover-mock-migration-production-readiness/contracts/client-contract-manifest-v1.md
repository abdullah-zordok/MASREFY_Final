# Client Contract Manifest v1

**Version**: 1.0.0
**Status**: Pre-implementation contract baseline; evidence cells advance per wave
**Baseline**: `65bc5fd2f8875c72c9885787e5c021e4c2576d09`
**Scope**: Every active Mobile service call and non-billing Admin repository call in Waves 1-9

**Declared active operations: Mobile 214; Admin 123.** SPEC-BE-014 owns no database entity or backend domain resource.

Each exact operation identifier below inherits every named policy profile. Within a grouped code span, a bare method name inherits the namespace of the first fully qualified identifier (for example, `mobile.auth.startPhone`, `verifyPhone` means `mobile.auth.verifyPhone`). A grouped row is valid only when every listed operation has the same source, endpoint family, mapping, authorization, offline, comparison, cutover, rollback, and evidence rules. Grouping never creates a wildcard: every callable method must be named once, and a row is split before its wave if any policy differs.

## Policy Profiles

### Mapping and errors

| Code | Request mapper | Response mapper | Error mapping | Unknown/malformed behavior |
|---|---|---|---|---|
| `MAP-STRICT` | Existing client input schema to the exact owner DTO; allowlist fields; integer minor units and ISO timestamps | Owner response schema to the complete client contract; preserve nullable/optional/version fields | Decode the flat safe error envelope and map only documented codes | Unknown field/state/error or malformed value raises explicit `contract_mismatch`; no coercion/fabrication |
| `MAP-FINANCE` | `MAP-STRICT` plus original idempotency key, expected version, currency, signed posting semantics | `MAP-STRICT` plus exact integer/version/source fields | Conflict/current-version and idempotency mismatch remain distinct | Any rounding, default sign, dropped account/category/payment field, or financial difference blocks the wave |
| `MAP-PAGE` | `MAP-STRICT` plus bounded `limit` and opaque cursor/after value | Preserve `items`, `nextCursor`/`nextPage`, `hasMore`, totals only when authoritative | Invalid/expired cursor is explicit | Never synthesize totals or truncate silently |
| `MAP-LOCAL` | Validate local input at the existing service/storage boundary | Return only local/device state | Existing local safe error | No network claim and no shadow requirement |
| `MAP-UNAVAILABLE` | No production request | Stable explicit unavailable result/error | `capability_unavailable` | Never call a mock or fabricate a success |

### Authentication and permission

| Code | Authentication | Permission requirements |
|---|---|---|
| `AUTH-OWNER` | Current ordinary Clerk session token; no custom template, role header, or service key | Server owner/RLS and any recent-auth rule |
| `AUTH-ADMIN` | Current ordinary Clerk Admin session token | Exact database permission plus server MFA/recent-auth/support-grant checks; UI state is not authority |
| `AUTH-META` | Owner session when available; public metadata only where the owner contract permits | No secret/restricted setting; capability flags remain server-owned |
| `AUTH-LOCAL` | None sent to a provider | Device OS/local-data permission only |

### Pagination, offline, shadow, cutover, rollback, and evidence

| Code | Behavior |
|---|---|
| `PAGE-NONE` | Single bounded resource/command |
| `PAGE-CURSOR` | Follow opaque cursors until requested page/result is complete; never infer offset totals |
| `SYNC-006` | Use registered server device ID, signed owner/device/domain cursor, bounded bootstrap/delta, mutation receipts, tombstones, acknowledge, and explicit conflicts |
| `OFF-CACHE` | Preserve last accepted local read with explicit freshness/unavailable state; never present it as a fresh live response |
| `OFF-QUEUE` | Preserve original operation ID/idempotency key, expected version, dependency order, pending/conflict state, retry and reconnect |
| `OFF-LOCAL` | Device-owned drafts/preferences/protected material remain in existing encrypted/local repository and survive cutover/rollback |
| `OFF-NONE` | Fail safely when offline; no invented result |
| `SH-STRUCT` | Compare contract version, canonical structural hash/count/state/version only; redacted difference codes |
| `SH-FIN` | `SH-STRUCT` plus exact integer money, ledger/source version, membership, and status; zero tolerance |
| `SH-NONE` | Local/device operation with no remote comparison |
| `CUT-Wn` | Wave n uses `shadow -> internal -> bounded-write -> full`; production selects live only |
| `RB-Wn` | Immediate switch to Wave n's recorded prior accepted config/image; preserve server data and client operation IDs; rerun reconciliation |
| `TEST-Wn` | Failing parity/selection regression, focused owner/client tests, wave security/performance/data/rollback gates, independent review, pushed-SHA remote CI |
| `EXT-*` | Named external proof remains open until genuine evidence; see `evidence/external-gates.md` |

## Manifest Completion Rules

- Before a wave starts, attach exact source/mapper symbols and owner OpenAPI operation IDs; split any grouped row whose policies or endpoint ownership differ.
- Before a wave commit, link every row to fresh focused test output and the wave evidence file; no `TEST-Wn` profile alone counts as evidence.
- External profiles link to a concrete record in `evidence/external-gates.md`; an open record is never a pass.
- A manifest verifier must prove unique operation IDs, fields/profiles present, no active billing operation, and no active operation without a live or explicit unavailable disposition.
