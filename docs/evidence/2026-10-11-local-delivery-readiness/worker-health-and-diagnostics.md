# Scoped worker health and extraction diagnostics

Local implementation on recovery base `68e198e0`. Only candidate source/configuration changed; no deployment, provider request, financial operation or device action was performed.

The existing container healthcheck selects a bounded local health record only for `MASARIFI_PROCESS_KIND=worker` with Analysis or Assistant scope. The API continues to probe its existing `/health/live` endpoint. A worker is healthy only after a completed successful poll, at its exact forty-character source SHA and matching scope. Startup, stopped, failed, future, malformed, wrong-source and stale records fail. Successful later polling can recover health after an infrastructure failure.

The record contains only source SHA, fixed scope/state and observation time. The worker publishes startup before polling, failure before logging an exception, and stopped after shutdown. A missing/unwritable health file logs a fixed failure; it never enables posting. The fixed `/tmp/ai-worker-health.json` writer creates a unique exclusive non-following temporary file with mode 0600 and atomically replaces the observation. The health command rejects files above 1024 bytes. Concurrent readers see a complete prior or new record. Persistent publication failure can leave an earlier ready record until its freshness bound expires; logs plus freshness catch that failure rather than a fabricated immediate OFF proof.

Freshness permits the greater of the existing Voice 180-second deadline and Assistant's configured lease (10–300 seconds), plus the poll interval. The claim limit is capped to concurrency, so one poll cannot silently enqueue multiple sequential full-duration claim waves. This is processing-loop liveness, not proof of real provider accuracy, customer acceptance, queue capacity or notification delivery.

Its inherited nonroot readonly container has isolated writable `/tmp`. General worker and API health contracts remain unchanged. A separately approved Assistant replacement must likewise configure this command and start period. Final image/environment pins and actual failure/staleness/shutdown rehearsal must be reviewed and observed before any rollout; old live workers still have no new verified health evidence.

Voice batch extraction now emits `VOICE_EXTRACTION_DECIDED` before persistence and `VOICE_BATCH_ACCEPTED` only after the existing acceptance call returns accepted. Fields are bounded event/eligible/skipped counts and existing server-enumerated skip-reason counts. Empty, all-skipped and eligible results remain distinct. Neither message means a financial transaction was posted. Commands, amounts, owner/session/claim/account IDs, transcripts, audio paths and provider contents are absent. This closes the future sanitized diagnostic gap without reconstructing the expired older recording or changing extraction, acceptance, cleanup or accounting policy.
